# Coding agent API workflow

Any coding agent can drive model profiling with HTTP JSON. The service runs the
registered Python runner in Colab; it never invokes a coding agent or LLM.
The dashboard displays results and is not required for execution.

## Service

Start `uv run python -m kernel_dashboard api` in a persistent terminal/process.
Default base URL: `http://127.0.0.1:8765`.

- `GET /api/health`: service readiness and discovery links.
- `GET /openapi.json`: machine-readable request and response documentation.
- `GET /api/guide`: this guide.
- `GET /api/runners`: registered runner IDs.

## Register code

Create a self-contained Python runner on the API server's filesystem. See
`runners/tiny_decoder.py` and the runner contract in README.md. Registration does
not import or run the file.

```sh
curl --fail-with-body --silent --show-error http://127.0.0.1:8765/api/runners \
  -H 'Content-Type: application/json' \
  -d '{"id":"optimized","path":"runners/optimized.py"}'
```

Relative paths resolve against the repository root. Absolute paths are accepted.
The path must identify an existing `.py` file on the API server. The bundled
`tiny_decoder` ID is reserved; register variants under a different ID.

## Submit and observe

```sh
curl --fail-with-body --silent --show-error http://127.0.0.1:8765/api/runs \
  -H 'Content-Type: application/json' \
  -d '{"runner":"tiny_decoder","gpu":"A100","dtype":"bf16","batch":1,"input_tokens":128,"output_tokens":16,"warmup":1,"baseline_repeats":5,"timeout_sec":7200}'
```

The response is HTTP **202**, with `id`, a `Location` header, and relative `links`
for status, result, cancellation, and the command log. Save the run ID before
performing another action. One collection can run at a time; HTTP **409** means
another collection owns the GPU job lock. Do not blindly retry a submission after
a network interruption: query `GET /api/runs` first to find an accepted request.

Poll `GET /api/runs/{id}` every 2–5 seconds. States:
`queued`, `allocating`, `preparing`, `profiling`, `downloading`, then
`completed`, `failed`, or `cancelled`. Check `error` on failure.

After `completed`, fetch `GET /api/runs/{id}/result`. After Nsight exits, a separate Python process measures the runner without
profilers or NVTX. Default `baseline_repeats` is 5; `timings` uses the median and
retains raw samples. Runner initialization/warmup is repeated per sample and is
excluded from measured inference time. Use fewer repeats for expensive model
initialization if needed. `timings.profiled` retains Nsight-run timings. Check
`timings.source`: `unprofiled` confirms independent timing; fallback sources and
warnings mean the baseline was not available. Kernel-row durations always come
from Nsight. Results include model
structure, phase timings, kernels, coverage, the overall `point`, and
`phase_points.prefill` / `phase_points.decode`. Check each point's `source`:
`measured` and `estimated` are different evidence. Missing decode in a 1-token
output run is intentional: the first output token is generated by prefill.
Use at least two output tokens to exercise decode.

Before declaring the job fully finished, wait for `finished_at` and inspect
`owns_session` / `cleanup_error`: analysis may complete just before VM teardown.
The configured collection timeout covers GPU allocation, setup, profiling and
result retrieval. There is no extra coding-agent timeout in this service.
Set your coding agent's own request/tool timeouts accordingly.

## Cancellation and files

```sh
curl --fail-with-body --silent --show-error -X POST \
  http://127.0.0.1:8765/api/runs/RUN_ID/cancel
```

Cancellation returns **202** promptly and sets `cancel_requested`. Poll the status
until cancellation and session cleanup finish. Repeated cancellation requests for
a terminal run are harmless. The worker stops only its own Colab session.

Download `GET /api/runs/{id}/artifacts/{name}` for `result.json`,
`artifacts.tar.gz`, or `commands.log`. Local files remain in `.runs/{id}/`.

For kernel improvements, check numerical correctness, collect baseline and
optimized versions with identical GPU/input/dtype settings, and compare measured
results. Do not claim improvement from estimates alone. The API does not select,
launch, or charge for a coding-agent model; the calling agent owns its reasoning,
conversation history and tool approvals.
